配方材料发送器
==============

适用环境
--------
- Minecraft 1.20.1
- Forge 47.4.20 或兼容的 47.x 版本
- Java 17 或更高版本
- EMI 1.1.24 或更高版本

可选 / 已适配模组
-----------------
- FindMeExtended 1.0.2 或更高版本：反转搜索，并共用它的容器黑名单。
- Applied Energistics 2 15.x：识别 AE2 ME 存储。
- 格雷科技（GTCEu / GTO 等）：电路自动配置。
- Architectury API 9.1.12 或更高版本：FindMeExtended 的依赖。

功能
----
1. 发送材料：在 EMI 配方界面悬停配方后，按住 Z 用滚轮选份数（按住 Shift 每次 8 份、按住 Ctrl 每次 64 份），松开发送。界面显示背包存量与待发送份数；份数超过目标容器容量时按容量发送，并提示“目标最多接收 X 份”。在配方树里点“合成”后，收藏栏里的合成条目同样可用。
2. 填满容器：按住 Alt 再按 Z，直接选背包能提供的全部份数。
3. 反转取回（需要 FindMeExtended）：按住反转键“~”再按 Z，统计背包与搜索范围内的材料，松开 Z 后只取回背包缺少的部分。反转键可在“选项 - 控制”里改成键盘或鼠标键，改后立即生效、重启保留。未安装时反转键仍会出现在控制设置里（否则改键存不住），但按住它按 Z 不传输，提示“反转搜索需要安装 FindMeExtended”；版本不兼容时提示需要 1.0.2 或更高版本。兼容层同时支持新旧包名（com.lai.findmeextended / com.lflamadeus.findmeextended）。
4. 反转模式不会移动背包原有材料（仍参与统计）。普通容器提取与背包溢出由 FindMeExtended 处理；装了 AE2 还会读取附近的 ME 存储。
5. 电路自动配置（需要格雷科技）：发送配方时把目标容器的编程电路调成配方要求的编号，提示框多显示一行“电路 #N”；目标支持电路调整时（输入总线、输入仓、单方块机器；格雷科技自己关掉电路槽的部件除外），电路先于材料写入。配方不使用电路时，只要目标有电路槽就把电路置空（提示“电路置空”）：格雷科技按搜索键匹配配方，残留的电路会让“不需要电路”和“要求该编号”的配方同时成为候选，可能跑错配方；清空与写入电路 0 对匹配等价，这里选真清空，因为电路 0 也是一块带 NBT 的编程电路物品，留在槽里容易被当成没生效。
   以下情况不改动电路：反转取回；目标没有电路槽（原版箱子、漏斗等，也不会显示“电路 #N”）；不是格雷配方或没能认出；电路已经是目标编号；电路槽里不是编程电路（只写编号、不置空）。提示行由客户端判断，实际改动由服务端判断。
   注意：要打开“输入总线 / 输入仓 / 单方块机器”的界面再按 Z。多方块机器的控制器界面没有电路槽，打开控制器发送不会改动电路。
6. 容器黑名单（FindMeExtended 提供，本模组共用）：手持黑名单工具（默认木剑，可在 config/findmeextended.json 的 COMMON.BLACKLIST_TOOLS 改成别的物品，可填多个）时，视距内的黑名单容器持续高亮：亮黄轮廓（CLIENT.BLACKLIST_HIGHLIGHT_COLOR，默认 #FFE533）加深灰半透明填充（CLIENT.BLACKLIST_FILL_COLOR 默认 #2D2D2D，不透明度 CLIENT.BLACKLIST_FILL_ALPHA 默认 0.52，设为 0 只剩轮廓）。每帧都画，不闪烁，关掉深度测试，被墙挡住也能看见；双箱子的两半都高亮；换上工具当帧生效。潜行 + 右键加入黑名单，潜行 + 左键移出；黑名单按维度存在存档里，只认坐标（拆掉容器再在同一坐标放一个新的仍算黑名单；坐标上没有容器时，下次高亮会自动清掉）。
   反转模式共用这份黑名单：被列入的容器既不计入“背包与周围现有 X 份”，也不会被取回；FindMeExtended 的“查找物品 / 取出物品”同样跳过。需要 FindMeExtended 1.0.2 或更高版本，更旧的版本没有这个接口，反转搜索退化为不排除任何容器。
   注意：AE2 的整个网络聚合视图无法按单个容器排除——存储总线把容器挂进网络后，物品是通过网络视图读到的，把那个存储方块列入黑名单不会让它的物品从网络视图里消失。

绑定容器
--------
1. 绑定：准星对准容器按绑定键（默认 B）即可绑定；对已绑定的容器再按一次绑定键，会直接跳到上次用过的那个容器，不再弹窗。
2. 发送：按住绑定键再按发送键（默认 Z），材料直接发往已绑定的主容器，不必先打开容器界面。发送模式优先级固定为“反转取回 > 发送到已绑定容器 > 正向发送”，松键顺序不影响结果。
3. 多个主容器：绑了多个时，松开发送键会弹出选择窗（鼠标点选、↑↓、Enter、1-9、Esc、滚轮；候选超过 8 个时出现搜索框，支持中文拼音）。
4. 管理界面：按 Ctrl+B 打开，可改名、删除（按钮先变红，3 秒内再点一次才真删）、高亮（世界里画红框闪 3 秒，隔着方块也看得见）。绑定的容器被拆掉时，那一行铺红底并标“容器已不在”，绑定本身保留，把容器放回原处就恢复。
5. 并列组：绑定时可选主容器 / 并列成员 / 从容器。材料按份均分，余数从主容器往后依次多分；某台装不下时整份顺延给组内还有空间的容器；从容器接收整组放满后的余量（只支持一级）。容器关系随时可在管理界面改。
6. 配方类别自动路由：在管理界面给主容器勾选它负责的配方类别。发送到已绑定容器时按类别自动挑容器，候选只有一个就直接发，多个才弹选择窗；没勾过类别的主容器视为“仅手动选择”，不参与自动路由，没有任何主容器负责该类别时不发送并提示原因。类别选择器支持类别名、机器名、类别 id 子串与中文拼音搜索，按命名空间分组，还可以只看当前机器登记过的类别。
7. 绑定数据存在玩家自己的持久数据里，多人服务器互不干扰；不设绑定数量上限，也不做距离限制。

构建
----
在项目根目录使用 Gradle Wrapper 执行 build 任务，产物在 build/libs。
