配方材料发送器
================

适用环境
--------
- Minecraft 1.20.1
- Forge 47.4.20 或兼容的 47.x 版本
- Java 17
- EMI 1.1.24 或更高版本
- FindMeExtended 1.0.2 或更高版本（可选，仅反转模式需要；1.0.2 起提供容器黑名单）
- Applied Energistics 2 15.x（可选，用于识别 AE2 ME 存储）
- Architectury API 9.1.12 或更高版本（FindMeExtended 的依赖）
- 格雷科技（GTCEu / GTO 等，可选，仅“电路自动配置”需要）

功能
----
1. 在 EMI 配方界面悬停配方后，按住 Z 使用滚轮选择份数（同时按住shift每次变动8份，按住ctrl每次变动64份），松开后将背包中的材料发送到当前容器。界面会显示背包存量与待发送份数；若选择份数超过目标容器可容纳的数量，将按目标容器能容纳的份数发送，并额外提示“目标最多接收 X 份”。
   在 EMI 配方树里点“合成”后收藏栏自动生成的那批合成条目同样可用：在收藏栏里悬停某个配方再按 Z，发送的就是它需要的材料。
2. 按住 Alt 再按 Z，可直接选择背包能够提供的全部配方份数；结合上一条，就等于把目标容器尽可能填满（例如背包有 47 份材料、目标容器只能放下 32 份，则发送 32 份；背包只有 16 份而目标能放下 32 份，则 16 份全部发送）。
3. 安装 FindMeExtended 后，按住反转键“~”再按 Z，会统计背包与 FindMeExtended 搜索范围内的材料；松开 Z 后，只从周围容器取回背包缺少的部分。反转键可以在“选项 - 控制”里自由改键（键盘或鼠标按键均可），改键后立即生效、重启后依然保留。未安装 FindMeExtended 时反转键仍会出现在控制设置里（这样改键才能被正确保存），但按住它按 Z 不会执行任何传输，而是提示“反转搜索需要安装 FindMeExtended”；已安装但版本不兼容时提示需要 1.0.2 或更高版本。兼容层按候选包名加载 FindMeExtended 的类（新版 com.lai.findmeextended、旧版 com.lflamadeus.findmeextended 都支持），因此该模组改名或改名前的版本都不会让反转搜索失效。
4. 背包中原有材料不会在反转模式下被移动（会参与统计）；FindMeExtended 负责执行普通容器提取和背包溢出处理。安装 AE2 后，会额外读取附近 AE2 ME 存储中的物品。
5. 安装格雷科技后，发送配方时会自动把目标容器的编程电路调整成该配方要求的编号。若配方在 EMI 里带有编程电路（例如激光焊接机按电路区分不同转子），提示框会多显示一行“电路 #N”；发送时若目标容器支持电路调整（普通输入总线、输入仓、单方块机器；被格雷科技自己关掉电路槽的部件除外），电路会先于材料写入。配方不使用电路时，只要目标容器有电路槽就把它的电路置空（提示框多显示一行“电路置空”），不做机型判断——机器支持哪些配方由格雷科技自己决定。之所以必须置空：格雷科技是按“搜索键”匹配配方的，不使用电路的配方不会产生任何电路键，机器里留着的电路编号不会妨碍它被选中——于是“不需要电路的配方”和“要求该编号的配方”会同时成为候选，谁先被搜到就跑谁，表现就是跑错配方；而清空电路槽与写入电路 0 对匹配完全等价，本整合包里也不存在显式要求电路 0 的配方；之所以真清空而不是写 0，是因为 GT 的电路 0 也是一块带 NBT 的编程电路物品，留在槽里容易被当成没生效。
   以下情况不会改动任何电路：处于反转取回模式；目标没有电路槽（原版箱子、漏斗等，这类目标连“电路 #N”的提示都不显示）；不是格雷配方、或没能认出配方对象；电路已经是目标编号；电路槽里放的不是编程电路（那种情况只写编号、不置空，不动玩家自己的物品）。提示行由客户端判断、是否真的改动由服务端判断，两边看的是同一件事（目标有没有电路槽），客户端判断错了最多差一行字。
   注意：请打开“输入总线 / 输入仓 / 单方块机器”的界面再按 Z。多方块机器（例如激光焊接机）的控制器界面本身没有电路槽——格雷科技的电路槽属于输入总线/输入仓，打开控制器再发送不会改动电路。原版箱子这类不是格雷机器的容器不会收到任何电路请求；目标没有电路槽或电路已经是目标编号时也不会发生写入。
6. 容器黑名单（由 FindMeExtended 提供，本模组共用）：FindMeExtended 1.0.2 起自带黑名单——手持黑名单工具（默认木剑，可在 config/findmeextended.json 的 COMMON.BLACKLIST_TOOLS 里改成别的物品，可填多个）时，视距内的黑名单容器持续高亮：亮黄轮廓（CLIENT.BLACKLIST_HIGHLIGHT_COLOR，默认 #FFE533）加深灰半透明填充（CLIENT.BLACKLIST_FILL_COLOR 默认 #2D2D2D，不透明度 CLIENT.BLACKLIST_FILL_ALPHA 默认 0.52，设为 0 就只剩轮廓），每帧都画不闪烁、关掉深度测试所以被墙挡住也能看见，双箱子的两半都会高亮，换上工具当帧就出高亮、不用等服务端往返。潜行 + 右键把目标容器加入黑名单，潜行 + 左键把它移出黑名单；黑名单按维度存在存档里、只认坐标，与方块实体无关（拆掉容器再在同一坐标放一个新的，仍然算黑名单；坐标上已经没有容器时会在下次高亮时自动清掉该条）。
   本模组的反转模式共用这份黑名单：被列入黑名单的容器既不计入“背包与周围现有 X 份”，也不会被取回；FindMeExtended 自己的“查找物品 / 取出物品”同样跳过它们。
   需要 FindMeExtended 1.0.2 或更高版本；更旧的版本没有这个接口，反转搜索会退化成不排除任何容器（其余功能不受影响）。
   注意：AE2 的“整个网络的聚合视图”无法按单个容器排除——存储总线把某个容器挂进网络后，物品是通过网络视图读到的，把这个存储方块列入黑名单不会让它的物品从网络视图里消失。

构建
----
在项目根目录使用 Gradle Wrapper 执行 build 任务。构建产物位于 build/libs。
